# Now 页面 Today 进度强化设计

## 背景

当前 `Now` 页已经规划了一个 `Progress` 区块，展示 `Today`、`This Week`、`This Month`、`This Year` 四项时间进度。用户反馈 `Today` 即使保留两位小数，也很难直观感受到时间流逝，因此需要只针对 `Today` 这一项做更强的时间感表达，同时继续保持页面整体克制、工具化的气质。

## 目标

- 只强化 `Today` 这一项的时间流逝感。
- 在保留百分比的同时，增加“距离今天结束还有多久”的实时倒计时。
- 让 `Today` 进度条具备更明确的当前位置感，而不是只有静态填充宽度。
- 让 `Today` 标签与剩余时间文本做底部对齐。
- 让 `Today` 进度条的推进感更明显，但仍保持克制。
- 将刷新频率调整为每秒一次。
- 兼顾 `prefers-reduced-motion`，避免多余装饰动画。

## 非目标

- 不调整 `This Week`、`This Month`、`This Year` 的展示结构。
- 不新增倒计日、已过时长、文案说明或第二层复杂时间条。
- 不引入扫光、呼吸、无限循环等装饰性动画。
- 不改动 `Now` 页除 `Progress` 区块之外的结构。

## 方案选择

已确认方案为“信息与视觉混合强化”：

- `Today` 保留当前百分比显示。
- 额外增加一个单独的剩余时间文本，格式为 `HH:MM:SS left`。
- `Today` 标签与剩余时间文本放在同一行，并做底部对齐。
- 在 `Today` 的进度条末端增加更清楚的细胶囊标记，跟随当前进度移动。
- 在 `Today` 进度条前沿增加一小段更亮的推进尾巴，增强前进感，但不做整条扫光。
- 刷新频率统一为 `1000ms`。

放弃其他方案的原因：

- 仅增加更多百分比位数，变化频率依旧偏慢，体感不足。
- 单做装饰型动效容易喧宾夺主，不符合页面现有风格。
- 再增加一层小时级或分钟级进度条，会让信息层级过重。
- 使用整条扫光会过于装饰化，容易破坏当前页面的安静感。

## 信息架构

`Progress` 区块仍然保留四项：

1. `Today`
2. `This Week`
3. `This Month`
4. `This Year`

其中只有 `Today` 调整为增强版信息结构：

- 主行：左侧 `Today + HH:MM:SS left`，右侧百分比
- 下方：横向细进度条，带当前位置标记

其他三项保持原结构：

- 主行：左侧标签，右侧百分比
- 下方：横向细进度条

## 组件与职责

### `src/components/now-time-progress.tsx`

- 继续作为客户端组件负责：
  - 持有当前时间状态
  - 每秒更新
  - 区分 `Today` 与其他三项的渲染差异
  - 在 `Today` 行渲染剩余时间和当前位置标记

### `src/lib/now-time-progress.ts`

- 增加与 `Today` 剩余时间相关的纯函数：
  - 计算今日剩余毫秒数
  - 格式化为 `HH:MM:SS left`

这样时间边界和格式化仍然集中在纯函数中，便于测试。

## 数据流

1. `NowPage` 继续提供 `initialTimestamp`。
2. `NowTimeProgress` 用初始时间完成首屏渲染。
3. 客户端每秒更新时间一次。
4. 每次更新时间后：
   - 重新计算四项进度
   - 额外计算 `Today` 距离次日零点的剩余时间
5. 使用新结果更新 `Today` 的数字和标记位置。

## 计算规则

### Today 剩余时间

- 起点仍然是当前时刻。
- 终点为次日 `00:00:00.000`。
- 剩余时间 = `次日开始 - 当前时间`。
- 文本格式固定为 `HH:MM:SS left`。
- `HH` 不限制在 23 内部之外的复杂格式，因为 `Today` 的剩余时间永远不会超过 24 小时。

### Today 当前位置标记

- 标记位置和 `Today` 进度条填充宽度使用同一份进度值。
- 标记锚定在填充条末端。
- 标记使用比当前更清楚的细胶囊或短竖条，而不是弱存在感的小圆点。

### Today 推进尾巴

- 在进度条前沿区域增加一小段更亮的高光尾巴。
- 高光尾巴只覆盖前沿局部，不横扫整条进度条。
- 推进尾巴与当前位置标记同步移动。

## 视觉与交互

### Today

- 百分比继续使用 `font-mono`。
- `Today` 标签与剩余时间文本放在同一行，用 `items-end` 做底部对齐。
- 剩余时间使用更小号等宽字显示。
- 颜色略弱于主百分比，但仍保持可读。
- 进度条高度可比其余三项略厚一点，但不要明显跳脱。
- 条尾使用更清楚的细胶囊标记。
- 条尾前方增加短促的亮尾，形成“推进头部”。
- 不做整条扫光或无限循环动画。
- 标记和亮尾不做独立装饰动画，只随真实时间推进。

### Reduced Motion

- 在 `prefers-reduced-motion: reduce` 下：
  - 保留数字更新
  - 保留进度条宽度变化
  - 去掉或弱化条宽、亮尾和标记位置的过渡动画

### Other Items

- `This Week`、`This Month`、`This Year` 不增加额外文本。
- 仍维持当前低对比细条和百分比布局。

## 刷新策略

- 统一从 `200ms` 调整为 `1000ms`。
- 原因：
  - `HH:MM:SS` 的变化粒度是秒级，没必要更高频刷新。
  - 可以减少不必要重渲染。
  - 仍然足够让时间流逝感直观成立。

## 测试策略

优先补充 `src/lib/now-time-progress.ts` 的纯函数测试，覆盖：

- `Today` 剩余时间在普通时刻的格式化
- 接近午夜时的边界值
- 零点时的剩余时间
- 进度与剩余时间使用同一个日边界

UI 层只做轻量接入，不新增复杂交互测试。

## 实施范围

本次增量实现只涉及：

- `src/components/now-time-progress.tsx`
- `src/lib/now-time-progress.ts`
- 对应测试文件

## 验收标准

- `Today` 行左侧显示 `Today` 和实时变化的 `HH:MM:SS left`，并且两者底部对齐。
- `Today` 进度条具有清晰但克制的细胶囊标记。
- `Today` 进度条前沿存在可感知的短亮尾，推进感比普通进度条更强。
- 刷新频率为 `1s`。
- `This Week`、`This Month`、`This Year` 保持简洁，不新增额外信息。
- 在减少动态效果偏好的系统设置下，没有多余动画感。
