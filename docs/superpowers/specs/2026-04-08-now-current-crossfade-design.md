# Now 页面 Current 图标切换淡入淡出设计

## 背景

`Now` 页的 `Current` 区块目前会定时切换软件图标和名称，但切换方式是瞬时替换，观感偏硬。用户希望“平滑一点”，并已确认采用最克制的方案：淡入淡出，不增加位移或缩放。

## 目标

- 让 `Current` 区块的软件图标切换从瞬时替换改为淡入淡出。
- 图标和名称同步过渡，避免图标和文字节奏不一致。
- 保持当前随机切换逻辑和切换节奏不变。
- 在 `prefers-reduced-motion` 下保留直接切换。

## 非目标

- 不修改图标来源、随机切换算法或时间区间。
- 不增加位移、缩放、翻页、旋转等额外动效。
- 不把 `Current` 区块改造成轮播或复杂动画组件。

## 方案选择

已确认方案为“交叉淡入淡出”：

- 当前项与下一项在一个固定尺寸容器中短暂重叠。
- 当前项淡出时，下一项淡入。
- 图标和名称作为同一组内容一起过渡。

放弃其他方案的原因：

- 上浮切换会让这块显得更“动”，不符合当前页面的克制感。
- 缩放切换存在存在感，但会让这块更像卡片动画而不是状态面板。

## 组件与职责

### `src/components/now-current-software.tsx`

- 继续作为唯一客户端组件负责：
  - 当前索引调度
  - 切换时机
  - 交叉淡入淡出渲染

### `src/lib/now-current-software.ts`

- 保持原有随机延迟与索引选择逻辑不变。
- 如有需要，只补充极小的常量，不新增复杂状态机。

## 交互与视觉

- 外层保持固定宽高，避免切换时布局跳动。
- 图标与名称使用绝对定位或重叠层进行短暂并存。
- 过渡只使用 `opacity`，不使用 `transform`。
- 动画时长应短于平均切换间隔，避免拖尾。
- `prefers-reduced-motion: reduce` 下去掉透明度过渡，直接替换。

## 数据流

1. 组件维护当前显示索引。
2. 定时器触发切换时，先生成下一个索引。
3. 将当前项与下一项同时放进渲染树中。
4. 当前项淡出，下一项淡入。
5. 过渡结束后，仅保留新项。

## 状态设计

建议最小状态为：

- `currentIndex`：当前已稳定显示的项
- `transitionIndex`：正在淡入的下一项，没有时为 `null`
- `isTransitioning`：当前是否处于过渡中

这样可以把“稳定显示”和“过渡中”拆清楚，避免直接替换索引导致无法交叉渲染。

## 性能考虑

- 同时渲染的最多只有两项，开销很小。
- 过渡只使用透明度，避免更重的布局和绘制影响。
- 不引入额外第三方动画库。

## 测试策略

优先补充 `src/lib/now-current-software.ts` 的小型测试或在组件内部保持逻辑简单，确保：

- 多个图标时仍然不会连续重复同一项
- 切换区间逻辑不变
- 组件在只有一个图标时不进入过渡状态

UI 动画本身不做复杂 DOM 动画测试，重点保证状态切换逻辑简单可控。

## 实施范围

本次实现预计只涉及：

- `src/components/now-current-software.tsx`
- 如有必要，少量调整 `src/lib/now-current-software.ts`
- 对应测试文件

## 验收标准

- `Current` 图标切换时不再瞬时跳变。
- 图标和名称一起淡入淡出。
- 不出现布局抖动或高度变化。
- `prefers-reduced-motion` 下不保留多余动画。
- 现有随机切换逻辑保持不变。
